# Ticket Collection and Booking API

Комплект содержит:

- `ticket-service.yaml` — спецификацию OpenAPI 3.0.3 первого сервиса (коллекция Ticket);
- `booking-service.yaml` — спецификацию второго сервиса `/booking`; модели Ticket и
  Problem подключаются из `ticket-service.yaml` через `$ref`;
- `index.html` — интерактивную документацию Swagger UI;
- `swagger-ui/` — локальная копия Swagger UI 5.27.1, документация открывается без CDN.

Развёрнутая документация: <http://217.65.79.114/>.

## Просмотр Swagger UI

Из корня репозитория запустите любой статический HTTP-сервер, например:

```bash
python3 -m http.server 8081
```

После этого откройте <http://localhost:8081/>. Запуск `index.html` напрямую через
`file://` может не загрузить спецификации из-за ограничений браузера.

## Принятые решения

- Нумерация страниц начинается с 1; размер страницы ограничен 100 элементами.
- Фильтры списка объединяются через `AND`, сравнение — точное.
- `sort` повторяется для многоуровневой сортировки, например
  `?sort=price,desc&sort=name,asc`.
- Некорректный синтаксис запроса даёт `400`, отсутствие ресурса — `404`, нарушение
  ограничений модели — `422`.
- Формулировка «все параметры передаются в URL» трактуется как требование к
  идентификаторам, пагинации, сортировке и фильтрам. Представление создаваемого или
  обновляемого Ticket передаётся JSON-телом, как принято в REST API.
- В исходной модели нет связи билета с человеком, хотя операция отмены требует
  удалить `person-id` из билетов. Поэтому в ответное представление Ticket добавлено
  серверное read-only поле `bookedPersonIds`. Оно управляется сервисом `/booking`
  и недоступно в обычных create/update-запросах первого сервиса.
- Продажа VIP-копии исходного билета с `price=null` возвращает `409`, поскольку
  удвоить отсутствующую цену невозможно.
